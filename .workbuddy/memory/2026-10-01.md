## fix: PDF 预览变下载（Content-Disposition 问题）
- 现象：点预览直接下载、预览界面空白
- 根因：COS 对 PDF 返回 Content-Disposition: attachment（强制下载）；匿名 URL 加 response-content-disposition=inline 返回 400；且无 CORS 头，前端 fetch 转 blob 也走不通
- 解法：新增 node-functions/api/preview.js 代理端点（/api/preview?key=...）——从 COS 拉文件并强制返回 Content-Disposition: inline，前端 iframe 走同源代理
  - 安全：只允许 files/ 或 data/ 前缀 + 禁止 .. 路径穿越；用 res.body 流式透传不落内存
  - materials-loader.js 里 PDF 预览 URL 改为 /api/preview?key=<key>
- commit 80b126c，已部署验证：/api/preview 返回 inline + application/pdf + 327KB，前端已切代理
- 教训：COS 对象可能被上传时写了 attachment 元数据，公共读也强制下载；同源代理是绕过 Content-Disposition 最稳的办法

## fix: Office(PPTX) 预览报「已重置连接」
- 现象：电路分析 课件1(电路分析复习.pptx, 中文路径) 用微软 Office Viewer 预览报「已重置连接」
- 根因：微软 view.officeapps.live.com 的服务器拉取不到腾讯 COS（成都）的文件，跨国网络问题
- 解法：Office 预览的 src 改走本站 EdgeOne 代理（location.origin + /api/preview?key=...&n=<文件名>），微软改从本站（全球CDN）拉文件
  - URL 追加 &n=<文件名> 让链接以原始扩展名结尾（.pptx），方便微软识别文件类型；代理忽略 n 参数
- 代理验证：/api/preview 返回 200 + 正确 content-type + inline + PK 头（0.56MB）
