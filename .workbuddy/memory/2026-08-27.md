## 根因定位并修复：「间歇性无法连接 / 403」= DNS 双记录

### 症状链
- 用户反馈 `sicau-jdxy-resource.cn` 间歇性无法连接 / 证书错误 / 手机端 403
- 之前多轮排查误判：证书缓存 → EdgeOne 回源域名错 → IPv6 不稳定建议禁 IPv6（全错）

### 真正的根因
- 域名 `sicau-jdxy-resource.cn` 在腾讯云 DNSPod 里**同时存在两条 @ 主机的 CNAME**（同默认线路）：
  - 第②条：CNAME → `sicau-jdxy-resource.cn.pages.dnsoe5.com`（EdgeOne Pages，正确，07-15 EdgeOne 加）
  - 第③条：CNAME → `scau-files-1440179010.cos.ap-chengdu.myqcloud.com`（COS 默认域名，08-01 残留）
- 同主机同线路两条 CNAME，DNS 解析时随机返回 → 走 COS 的 IPv4 请求 `/` 返回 403 AccessDenied，走 Pages 的 IPv6 正常 200 → "时好时坏"

### 决定性证据（DoH 查询）
- 删前：A 记录→COS（183.66.100.19/.32），AAAA→Pages；`--resolve` 强制 COS IPv4 → 403，强制 Pages IPv6 → 200
- 删后：A/AAAA/CNAME 全部 → Pages

### 修复
- 用户删除第③条 COS CNAME（DNSPod 控制台）
- 验证：正常/IPv4/IPv6 各 5 次全部 200，Server 统一 edgeone-pages

### 关键认知（重要，避免再犯）
- **排查"间歇性"先查 DNS 记录是否多源/多线路分流**——同一主机多条 CNAME 会随机分流
- 用多个 DoH（阿里 dns.alidns.com / 腾讯 doh.pub / Cloudflare）交叉查 A/AAAA/CNAME，能暴露线路分流不一致
- `--resolve domain:port:ip` 强制指定后端，是定位"某条路不通"的利器
- COS 默认域名（`xxx.cos.region.myqcloud.com`）不提供首页索引文档，访问 `/` 必 403；只有 cos-website 域名（`xxx.cos-website.region.myqcloud.com`）才映射 index.html
- 资料/数据访问走 COS 桶完整域名（`scau-files-1440179010.cos.ap-chengdu.myqcloud.com`），不经 `sicau-jdxy-resource.cn`，所以删域名 COS 记录不影响资料下载
